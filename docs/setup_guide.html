ARCore fetcher セットアップ手順

Android 端末で多視点画像とカメラ姿勢を撮影し、データを取り出すまで。
Android の開発経験がなくても進められるように書いてあります。

  1. 必要なもの
  2. Android Studio を入れる
  3. プロジェクトを開く
  4. 端末を開発者モードにする
  5. 端末をつないでビルドする
  6. 撮影する
  7. データを取り出す
  8. 中身を確認する
  9. うまくいかないとき

1 必要なもの

もの条件
Android 端末 ARCore 対応機種であること。Google の ARCore supported devices に載っているか確認してください。Android 7.0 (API 24) 以上。
USB ケーブル充電専用でなくデータ転送できるもの。ここでつまずく人が多いです。
PCWindows / macOS / Linux のいずれか。空き容量 10GB 程度。
ネット接続初回ビルドで数 GB ダウンロードします。

2 Android Studio を入れる

  1. developer.android.com/studio から Android Studio をダウンロードしてインストールします。
  2. 初回起動時にセットアップウィザードが出ます。Standard を選んで進めれば、 必要な Android SDK と JDK が一緒に入ります。

このアプリは JDK 17 でビルドします。Android Studio に同梱の JDK （JetBrains Runtime）で足りるので、別途 Java を入れる必要はありません。

3 プロジェクトを開く

  1. Android Studio の最初の画面で Open を選びます。
  2. この ARCore_fetcher フォルダ（settings.gradle.kts がある階層）を選びます。 中の app フォルダではありません。
  3. 右下に Gradle sync の進捗が出ます。初回は数分〜十数分かかります。 Sync finished になれば成功です。

Gradle wrapper が見つからない、と言われたら。 このリポジトリには gradle-wrapper.jar を含めていません。 通常は Android Studio が自動生成しますが、しなかった場合は Gradle をインストールしてから、プロジェクトのルートで次を実行してください。

gradle wrapper --gradle-version 8.9

4 端末を開発者モードにする

端末側の操作です。メーカーによって文言が少し違います。

  1. 設定 → デバイス情報 を開く
  2. ビルド番号 を 7 回連続でタップする （「これでデベロッパーになりました」と出ます）
  3. 設定 → システム → 開発者向けオプション を開く
  4. USB デバッグ を ON にする

5 端末をつないでビルドする

  1. USB ケーブルで端末と PC をつなぎます。
  2. 端末に「USB デバッグを許可しますか？」が出たら 許可。 「このパソコンからのUSBデバッグを常に許可する」にチェックを入れておくと楽です。
  3. Android Studio の上部、実行ボタン（▶）の左にあるドロップダウンに端末名が出ることを確認します。
  4. ▶ Run を押します。ビルドが走り、アプリが端末にインストールされて起動します。
  5. アプリがカメラの使用許可を求めるので許可します。

最初のビルドで Incompatible Gradle JVM version が出たら。 Android Studio が Gradle の実行に選んだ JDK が新しすぎる、という意味です。 よく出るので驚かないでください。直し方はステップ 9 の表の 1 行目にあります。

ARCore 未導入の端末では、起動時に Google Play Services for AR のインストールを促されます。 画面の指示に従って入れてください。これは Google 製の公式コンポーネントです。

Sync と Build は別物

下部パネルのタブが Sync と Build Output に分かれています。 ここを取り違えると「成功したのに何も起きない」と混乱するので、先に区別しておきます。

タブ何をしているいつ走るか
Sync 設定ファイル（*.gradle.kts）を読み、必要なライブラリを取ってくる。 あなたが書いた Kotlin のコードには触らない プロジェクトを開いたとき、設定を変えたとき
Build Output Kotlin のコードを実際にコンパイルし、アプリを組み立てる ▶ Run を押したとき

Sync が BUILD SUCCESSFUL になっても、コードはまだ一行もコンパイルされていません。 コンパイルのエラーは ▶ Run を押して初めて出ます。

「おすすめ」のポップアップは無視してよい

右下に通知が出ることがありますが、エラーではありません。 青い ⓘ が付いているものは提案です。赤い ! だけがエラーです。

よく出る通知どうするか
Project update recommended
（AGP のアップグレード提案）		 今はやらない。 ˅ で畳んで閉じる。 アプリが実機で動くのを確認するまでは、ツールチェーンのバージョンを動かさないこと。 動かすと、次にエラーが出たときコードのせいか更新のせいか切り分けられなくなります
Migrate to Gradle Daemon toolchain Ignore を押す。このアプリには必要ありません
New Minor Gradle Version Available そのままでよい。ⓘ の情報表示です

6 撮影する

アプリを起動するとタイトル画面が出ます。 撮影を行う を押すとカメラが起動し、画面上部に現在の状態が表示されます。 操作に迷ったら、タイトル画面か撮影画面の 使い方 を開いてください。

  1. 端末を持ってゆっくり左右に動かします。 上部の表示が PAUSED から TRACKING に変わります。
  2. TRACKING になっても、撮影 ボタンはまだ押せません。 上部に「VIO 収束待ち… 継続 x/3.0 秒・移動 x/0.15 m」と出ている間は、 ARCore が自己位置推定を収束させている途中です。 3 秒ほど、15 cm 以上動かし続けてください。 条件が揃うと撮影ボタンが有効になります。
    この待ち時間は飾りではありません。収束前に撮ると、画像には写っているのに カメラ姿勢だけが見当違いの方向を向いたフレームができ、あとから直せません。
  3. 撮影 ボタンで 1 枚ずつ撮ります。
  4. 対象のまわりを回り込みながら、視点を変えて撮ります。 目安は 30〜100 枚。同じ場所から連写しても情報は増えません。
  5. 撮り終わったら 書き出し ボタンを押します。

うまく撮るコツ

  • 明るい場所で撮る。暗いとトラッキングが外れます
  • 速く振らない。ブレるとトラッキングが外れます
  • 隣り合う写真が 7 割くらい重なるように、少しずつ動かす
  • 無地の壁や鏡、透明なものは苦手です

TRACKING が外れた状態（PAUSED）で撮った写真も、 捨てずにそのまま記録されます。 どれを使うかは撮影後に選べるようにしてあるので、気にせず撮り続けてかまいません。

7 データを取り出す

書き出し を押すと、撮影データが ZIP にまとめられ、 完了ダイアログが出ます。取り出し方は 2 つです。

  • 端末に保存 … 保存先（ダウンロードや Google ドライブ）を選んでコピーします。 アプリをアンインストールしても残るのはこちらです
  • 共有して送る … Android の共有シートを開きます。メールや AirDrop など、 端末に入っている転送手段で PC に送れます

取り出しに失敗しても撮り直しにはなりません。 完了ダイアログは画面の外をタップしても戻るキーでも閉じないので、 保存先の選択や共有シートをキャンセルしても、そのまま押し直せます。 ダイアログを閉じたあとでも、タイトル画面の 保存済みデータ から 同じ ZIP をいつでも開き直せます。

ZIP の中身はこうなっています。

capture_20260920T103104/
├── transforms.json
└── images/
    ├── 000000812345678901.jpg
    ├── 000000812378901234.jpg
    └── ...

transforms.json に、各写真のカメラ位置・向き・レンズのパラメータが入っています。 写真の EXIF ではなく、この JSON が唯一の正しい情報源です。

ファイルは端末内の Android/data/<アプリのパッケージ名>/files/captures/ にも残ります。 USB でファイル転送しても取り出せますが、アプリ内の「保存済みデータ」のほうが簡単です。 ただしこの場所はアプリをアンインストールすると消えるので、 残したいデータは 端末に保存 で外に出しておいてください。

8 中身を確認する

PC に取り出した ZIP を展開し、撮れているかどうかをざっと確かめます。 transforms.json はテキストファイルなので、そのままエディタで開けます。

  • frames の数が、撮った枚数と合っているか
  • images/ の中のファイル数が frames の数と同じか
  • w と h が、実際の写真の解像度と一致しているか （写真をプレビューで開けばピクセル数が見られます）
  • tracking_state が TRACKING のフレームがどれくらいあるか。 ほとんど PAUSED なら、明るい場所で撮り直したほうがよい結果になります

解像度だけは必ず見てください。 w / h と実際の写真のピクセル数が食い違っていると、 レンズのパラメータ（fl_x など）も一緒にずれています。 この場合はアプリ側の不具合なので、実際の解像度と JSON の値を控えておいてください。

9 うまくいかないとき

症状対処
Run ボタンの横に端末が出てこない ケーブルがデータ転送対応か確認。USB デバッグの許可ダイアログを見落としていないか。 別の USB ポートも試す。
Incompatible Gradle JVM version
（The project's Gradle version 8.9 is incompatible with the Gradle JVM version …）		 Gradle を動かす JDK が新しすぎます。プロジェクトのコードは無関係で、 ビルドが始まる前に止まっています。
Build Output に出ている Apply compatible Gradle JDK configuration and sync を押せば直ります。
手動なら Settings → Build, Execution, Deployment → Build Tools → Gradle → Gradle JDK を、Android Studio 同梱の JBR （jbr-21／「Android Studio default JDK」）に変えて Sync。 候補に無ければ Download JDK… から 17 を選ぶ。
Gradle sync が失敗する ネット接続を確認して File → Sync Project with Gradle Files をもう一度。 それでも直らなければ File → Invalidate Caches → Invalidate and Restart。
「この端末は ARCore に対応していません」 対応機種一覧に載っているか確認してください。非対応端末では動きません。
いつまでも PAUSED のまま 明るい場所へ移動し、模様のある面（机の木目、本棚など）に向けてゆっくり動かす。 真っ白な壁や暗い部屋では起動しません。
「まだ 1 枚も撮影していません」と出る 撮影ボタンを押す前に書き出しを押しています。先に何枚か撮ってください。
写真が思ったより粗い 端末が対応している CPU 画像の最大解像度を使っていますが、 機種によっては 640x480 止まりです。transforms.json の w / h に、そのとき保存された解像度が入っています。
書き出されるデータの形式は、リポジトリの README.md に説明があります。
